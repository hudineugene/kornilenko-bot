# Telegram-бот Construcciones Kornilenko

Telegram-бот для клиентов агентства недвижимости и веб-панель управления им.
Код разбит на модули в папке `src\` (см. «Устройство кода»). Для работы бота
npm-зависимости не нужны; для сборки нужен только esbuild. Для клиента бот
поставляется как один файл `bot.exe`.

Владельцу, который не программист, — одна страница «Что делать, если…»:
[docs/runbook.md](docs/runbook.md) (бот не отвечает, забыл пароль, восстановление
из копии, обновление и откат).

## Запуск

| Что | Команда |
|---|---|
| Рабочий запуск с журналом и перезапуском после сбоя | `powershell -ExecutionPolicy Bypass -File start-bot.ps1` |
| Запуск из исходников (нужен Node.js 22.12+) | `node bot.js` |
| Тесты | `npm test` |
| Сборка `dist\bot.exe` | `npm run build` |
| Остановить бота, дождавшись сохранения | `tools\stop-bot.ps1` (или Ctrl+C в окне бота) |
| Сменить пароль панели, если войти не получается | `.\bot.exe --reset-password` (из исходников — `node tools\set-panel-password.js`); бот при этом должен быть остановлен |
| Песочница: отдельные данные, порт и пароль `sandbox-pass` | `node tools\sandbox.js` |
| Пройти бота глазами клиента на песочнице | `node tools\walk-client.js` |

После запуска панель открывается по адресу http://127.0.0.1:3000. При первом
запуске панель попросит токен бота и пароль администратора. Первичная
настройка доступна только с этого компьютера.

Журнал бот ведёт сам: пишет в `logs\bot.log` всё, что выводит на экран, и,
когда файл вырастает больше 5 МБ, переносит прежний в `bot.log.1` и продолжает
в новом. Журнал ведётся и при запуске `bot.exe` двойным щелчком. Если бот
завершился с ошибкой, `start-bot.ps1` перезапускает его через 5 секунд; если
бот падает три раза подряд сразу после старта (например, занят порт), скрипт
останавливается.

**Остановка.** Штатно — Ctrl+C в окне бота. Закрытие окна, выход из учётной
записи и выключение Windows приходят боту одним сигналом (SIGTERM на Windows
не существует), и времени у него немного: система ждёт несколько секунд и
гасит процесс. Поэтому бот сначала сохраняет данные и только потом пытается
сообщить администратору об остановке — сообщение может и не успеть уйти.
Принудительное завершение (диспетчер задач, отключение питания) не оставляет
времени вовсе: такую остановку бот замечает при следующем запуске по метке
`bot-running.json` и сообщает, когда примерно это случилось.

**Сообщения о работе бота** приходят главному администратору в Telegram
(отключаются в «Настройки» → «Уведомления администратору»):

- «🟢 Бот запущен» — как только бот связался с Telegram, с тем, когда и почему
  он был остановлен и сколько длился перерыв;
- «🔴 Бот остановлен» — с причиной: Ctrl+C, закрытое окно или выключение
  компьютера, завершение процесса;
- «⏸ Бот выключен в панели» / «▶️ Бот включён в панели»;
- «📶 Связь с Telegram восстановлена» — если её не было дольше 3 минут;
- «❗ Внутренняя ошибка бота» — не чаще раза в час, бот при этом продолжает
  работать. Если бот остановился без этого (сбой, выключение
компьютера, принудительное завершение), при следующем запуске администратор
получает сообщение, когда примерно это произошло. Признак работы —
файл `bot-running.json`, который бот обновляет раз в минуту и удаляет при
штатной остановке.

**Вход в панель** сохраняется между перезапусками бота: сессии лежат в
`bot-sessions.json` (только SHA-256 хеши cookie, войти по ним нельзя).

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт веб-панели |
| `ADMIN_HOST` | `127.0.0.1` | Адрес, на котором слушает панель. `0.0.0.0` открывает её для сети — **по HTTP без шифрования**, только в доверенной сети |
| `ADMIN_ALLOWED_HOSTS` | — | Дополнительные имена хоста для панели через запятую (по IP-адресу и `localhost` панель открывается и без этого) |
| `BOT_DATA_FILE` | `bot-data.json` рядом с программой | Файл данных |
| `BOT_MEDIA_DIRECTORY` | `bot-media` рядом с файлом данных | Хранилище фотографий |
| `NO_AUTO_OPEN` | — | `1` — не открывать браузер при старте |
| `BOT_LOG_FILE` | `logs\bot.log` рядом с файлом данных | Куда писать журнал |
| `BOT_ALLOW_SECOND_COPY` | — | `1` — разрешить второй экземпляр при свежей метке `bot-running.json`. Нужен только для тестов; на живых данных второй экземпляр не запускайте |
| `BOT_NO_START` | — | `1` — загрузить модули, не запуская бота (тесты) |
| `TZ` | часовой пояс из настроек | Бот выставляет его сам по настройкам компании; вручную не задают |
| `CLOUDFLARED_PATH` | `cloudflared.exe` рядом с программой | Путь к `cloudflared.exe` для доступа из интернета |

## Данные

- `bot-data.json` — настройки, токен бота, хеш пароля, контент, пользователи и
  обращения. Запись атомарная (временный файл + переименование).
- `bot-data.json.bak` — проверенная копия, обновляется не чаще раза в час.
  Если основной файл повреждён, бот при старте поднимается из `.bak` или из
  самого свежего снимка в `backups\`. Повреждённый файл сохраняется как
  `bot-data.json.corrupt-<дата>`, а в журнале ошибок панели появляется запись.
- `bot-media\` — фотографии. Имя файла — SHA-256 его содержимого, поэтому одно
  и то же фото, загруженное для нескольких языков, хранится один раз.
- `backups\` — снимки данных, которые создаются автоматически перед
  обновлениями:
  - `pre-upgrade-v<старая>-to-v<новая>-<дата>.json` — файл данных в точности
    таким, каким он был до перехода на новый формат (новая версия бота при
    первом запуске). Делается один раз на каждый переход. Чтобы откатиться
    на прежнюю версию бота, остановите бота, верните прежний `bot.exe` и
    скопируйте этот файл на место `bot-data.json`;
  - `pre-media-migration-…` и `pre-media-dedupe-…` — перед переносом
    фотографий в отдельное хранилище.
- `backups\daily\` — ежедневный снимок `bot-data.json` (создаётся при запуске
  и затем раз в сутки, хранятся последние 14). Фотографии, на которые ссылаются
  снимки, лежат в `backups\media\`: каждый файл копируется один раз, лишние
  удаляются вместе со старыми снимками. Если в `bot-media\` не хватает фото,
  при старте бот сам возвращает его из `backups\media\`.
  Чтобы откатиться на снимок, остановите бота и скопируйте нужный
  `backups\daily\bot-data-<дата>.json` на место `bot-data.json`.
- Резервная копия из панели (`.json.gz`) содержит всё, включая фотографии.
- **Копия в Telegram** («Настройки» → «Копия данных в Telegram»): раз в
  неделю бот присылает в админ-чат файл `kornilenko-backup-<дата>.kbk` со
  всеми данными, кроме фотографий (они вместе больше лимита Telegram в
  50 МБ). Файл зашифрован AES-256-GCM ключом из пароля копии (scrypt); сам
  пароль нигде не хранится, в `bot-data.json` лежит только ключ, в браузер он
  не передаётся. Включить копию или сменить пароль можно только с паролем
  администратора. Восстановление: «Резервная копия» → «Восстановить» → файл
  `.kbk` → пароль копии; после восстановления копию нужно включить снова.
  Фотографии храните отдельно: если их файлов нет на компьютере, данные всё
  равно восстанавливаются, а панель пишет, сколько фото нужно загрузить
  заново. В файл резервной копии из панели ключ копии не попадает.

`DATA_VERSION` в `src\data-format.mjs` — версия формата данных (сейчас 43). Миграции,
которые меняют сохранённые данные, выполняются один раз — только для файлов
более старой версии. Новую миграцию закрывайте условием по
`storedVersion` (см. `normalizeLoadedData`) и увеличивайте `DATA_VERSION`,
иначе она будет срабатывать при каждом запуске и затирать правки
администратора. Перед повышением версии бот сам кладёт копию файла в
`backups\pre-upgrade-vX-to-vY-….json`, а более старый `bot.exe` на файле от новой
версии не запускается. Тест `tests\data-version.test.js` хранит отпечаток
формата: изменили формат — обновите версию и отпечаток вместе.

## Персональные данные

В карточке пользователя в панели есть блок «Персональные данные»:
«Выгрузить данные» скачивает JSON со всем, что бот хранит о человеке
(карточка, история, обращения); «Удалить все данные» стирает карточку,
историю, избранное, обращения и связи для ответов. В ежедневных снимках
данные остаются, пока снимок не удалится (14 дней). Сообщения, уже
отправленные в админ-чат Telegram, бот удалить не может.

## Уведомления администратору

Режим выбирается в настройках панели:

- **Только обращения и заявки** (по умолчанию): в Telegram приходят только
  обращения, а активность за вчера — одной сводкой после 9:00 (новые
  пользователи, сообщения, обращения, какие разделы открывали).
- **Все действия пользователей сразу**: каждое действие клиента отдельным
  коротким сообщением.

Уведомление об обращении выглядит так:

```
📩 Новое обращение: вопрос по объекту
👤 Мария · ES
📞 +34 600 111 222
🔖 Sierra Verde
Узнать цену

↩️ Ответьте на это сообщение — ответ получит клиент.
[⏳ В работу] [✅ Закрыть]
```

Телефон показывается, если клиент его уже оставлял; язык клиента — после
имени («· ES»). Уведомление о фото, голосовом или файле приходит
ответом на копию этого сообщения, так что видно, к чему оно относится.

Внизу карточки — строка состояния («🆕 Ждёт ответа», «⏳ Ведёт: Мария, с 12:40», «💬 Ответ: Олег, 12:41», «✔️ Закрыта»). Она меняется сразу во всех чатах (администратора и менеджеров): видно, кто взял и кто уже ответил. Если нажать «В работу» на заявке, которую уже ведёт коллега, бот спросит «Заявку ведёт Мария. Забрать себе?», а прежнему ведущему сообщит, если заявку забрали. Напоминания приходят о каждом клиенте, который ждёт ответа (в том числе написавшем после ответа менеджера), тому, кто ведёт заявку.

Кнопки под уведомлением меняют статус обращения в панели; у закрытого
обращения появляется «↩️ Открыть снова». Нажатия принимаются только из
админ-чата.

Переписка с клиентом — одно обращение: пока оно не закрыто и клиент пишет в
течение 3 дней (в том числе после ответа менеджера: «Да, давайте завтра»),
его сообщения добавляются в то же обращение, а администратор получает
«📩 Новое сообщение в заявке». Закрытое обращение не продолжается — новое
сообщение открывает новое. Подтверждение «Сообщение получено» клиент получает
на первое сообщение и снова — если перед этим молчал больше 10 минут. Больше 20 новых обращений в час от
одного человека не создаётся. Лимиты уведомлений раздельные: лишняя навигация
(больше 15 за 10 минут) тихо отбрасывается, а на поток сообщений (больше 20 за
10 минут) администратор получает одно предупреждение.

Админ-чат — это обычно ваш личный чат с ботом. Если написать туда что-то не
ответом на уведомление, бот не принимает это за обращение, а подсказывает, как
ответить клиенту. Меню, анкеты и автоответы при этом работают — бота можно
проверять «как клиент». В групповом чате менеджеров бот отвечает только на
команды и ответы на уведомления: остальное — разговор сотрудников.

Ответ на уведомление в Telegram уходит тому, к кому уведомление относится.
Связка «уведомление → пользователь» хранится в данных (`adminReplyTargets`),
текст уведомления для этого не используется: в нём есть имя и сообщение
пользователя, и их можно подделать.

### Команды в админ-чате

В админ-чате и чатах менеджеров в меню команд есть (клиенты их не видят):

- `/inbox` — обращения, которые ждут ответа: новые, которые никто не взял, и
  те, где клиент написал после ответа менеджера. Каждое приходит заново с
  кнопками — на него можно сразу ответить. Показываются 10 самых давних;
  менеджер видит свободные и свои.
- `/viewings` — просмотры сегодня и завтра (⏳ — ещё не подтверждён) и заявки
  на другие даты, которые ждут подтверждения.
- `/stats` — сегодня: новые пользователи, сообщения, обращения, сколько ждут
  ответа; с понедельника: клиенты, обращения, записи на просмотр.

Меню команд обновляется при запуске бота и при смене админ-чата или списка
менеджеров. «⏳ Сейчас без ответа» в итогах недели считается так же, как
`/inbox`.

### Напоминания о заявках без ответа

Если обращение всё ещё «новое» и на него никто не ответил (ни из панели, ни
из Telegram), через заданное время бот присылает напоминание:

```
⏰ Нет ответа 3 ч: вопрос менеджеру
👤 Мария · RU

Есть ли квартиры до 200 000 €?

↩️ Ответьте на это сообщение — ответ получит клиент.
[⏳ В работу] [✔️ Закрыть]
[📌 Напомнить завтра]
```

Срок задаётся в «Настройки» → «Уведомления администратору» → «Напоминать о
заявках без ответа»: 1, 2 (по умолчанию), 4, 8 часов, сутки или «Не
напоминать». Напоминания приходят только в рабочее время (см. «Рабочее
время»; если оно не задано — с 9:00 до 21:00): о том, что осталось без
ответа за ночь, бот напомнит утром. О каждом обращении — один раз.
Обращения старше 7 дней не напоминаются. За одну проверку (раз в 15 минут)
приходит не больше пяти напоминаний; об остальных бот сообщает одной строкой.

### Дата следующего контакта

В карточке обращения в панели — «Связаться с клиентом»: дата и, если нужно,
время. В этот день бот присылает в админ-чат «📌 Пора связаться с клиентом»
с текстом обращения, телефоном клиента и заметкой; на это сообщение можно
ответить, как на уведомление. Без времени напоминание приходит в начале
рабочего дня. Кнопка «📌 Напомнить завтра» под уведомлением ставит дату в одно
нажатие (при заданном рабочем времени — следующий рабочий день). Обращения с
датой на сегодня видны на главной панели в «Требует внимания».

### Итоги недели

По понедельникам в начале рабочего дня (по умолчанию в 9:00) главный
администратор получает итоги прошлой недели: новые клиенты и обращения в
сравнении с неделей раньше, типы обращений, просмотры, сколько обращений
сейчас без ответа, объекты с наибольшим числом обращений, источники клиентов
и рассылки. Если были сделки (обращение переведено на этап «Сделка»), в
отчёте появляется строка «🤝 Сделок» со сравнением; дата сделки (`wonAt`)
записывается в момент перевода на этот этап.

Те же цифры — на странице **«Отчёт»** (отдельный пункт меню; на телефоне — «Ещё → Отчёт»; на «Сегодня» есть строка недели со ссылкой): сверху итоги недели одной
страницей (плитки «Новых клиентов», «Заявок», «Записались на просмотр», «Сделок», «Без
ответа сейчас» со сравнением, источники и объекты), переключатель «Прошлая /
Эта, пока идёт» (эту сравнивают с тем же отрезком прошлой недели) и кнопка
«Скопировать текстом» — тот самый текст, что бот присылает в Telegram. Числа
считает бот (`weeklyReportData` в `src
otices.mjs`), панель только показывает,
поэтому в Telegram и на экране они не расходятся. Прежние 30-дневные
таблицы сложены под «Подробнее».

### Несколько менеджеров

«Настройки» → «Менеджеры»: имя и Chat ID каждого (менеджер открывает бота,
отправляет /myid и присылает номер), затем «Отправить тест». Уведомления о
заявках, напоминания о них и фото от клиентов приходят и администратору, и
всем менеджерам. Ответить клиенту может любой — ответом на уведомление;
подтверждение «Сообщение отправлено» приходит тому, кто ответил. «⏳ В работу»
закрепляет заявку за нажавшим («взял(а): Мария» в панели и в списке
обращений), напоминание «Пора связаться» приходит тому, кто взял заявку.
Сводки, итоги недели, коды входа из интернета и копии данных приходят только
главному администратору. В `adminReplyTargets` ключи уведомлений в чатах
менеджеров имеют вид `<chat id>:<message id>`.

**Передача клиента.** В карточке диалога рядом с «Ответственный менеджер» —
кнопка «Передать…» (`POST /api/inquiries/:id/transfer`): заявка переходит к
выбранному, а ему в Telegram уходит обычное уведомление, на которое можно
ответить. Все открытые заявки человека сразу (отпуск) — «⋯ → Передать всех
клиентов менеджера…» (`POST /api/inquiries/transfer`, `from` пустой — «без
менеджера»): новому приходит одна сводка, закрытые заявки остаются как были.
Панель честно пишет, дошло ли уведомление. Ответственный хранится именем, поэтому
при переименовании менеджера (или главного администратора) имя в его заявках
меняется само.

### Счётчик обращений

Число обращений, которые ждут ответа, стоит рядом с разделом «Обращения» в
меню панели. Пока вкладка открыта, панель обновляет данные каждые 45 секунд,
но не трогает форму, которую вы в этот момент заполняете.

## Панель управления

Панель открывается по адресу http://127.0.0.1:3000. В шапке — разделы, поле
общего поиска (клиенты по имени, @username и телефону, объекты по названию,
номеру и городу, сообщения по всей переписке) и колокольчик. На телефоне разделы
переезжают в нижнюю панель, а поиск прячется за значком 🔍.

| Раздел | Что внутри |
|---|---|
| **Сегодня** | Пока не всё готово к запуску — блок «Готовность к запуску» (токен, чат заявок, каталог, политика, контакты, лицо агента, копия вне компьютера, канал, первая заявка) с кнопками «Настроить»; при полной готовности он исчезает. Состояние бота со списком «здоровья» (Telegram, диск, копия, файлы, каналы). Если панель не достаёт до бота (остановлен, перезапускается), над шапкой появляется красная полоса «Нет связи с ботом» — она уходит сама, когда бот вернётся и переключатель «включён/выключен», цифры за 7 дней, «Что сделать сейчас» (без ответа, неподтверждённые просмотры, ошибки, заявки в группу), график сообщений по дням. Если в команде два и больше менеджеров, над «Списком дел» появляется переключатель «Все / Мои» и выбор «Я —»: «Мои» оставляют дела клиентов, закреплённых за выбранным человеком, и клиентов без менеджера (с пометкой) (кто «я», панель не знает — выбор запоминается в этом браузере) |
| **Клиенты** | «Диалоги» — переписка с каждым клиентом: ответы, вложения, реакции, ответственный, следующий контакт; «Следующие шаги» — просроченные, сегодняшние и будущие контакты; «Воронка» — этапы продажи; «База клиентов» — карточка клиента: контакты, язык, источник, интересы, запрос, заявки, личное сообщение |
| **Просмотры** | Недельный календарь, очередь подтверждения и история встреч, онлайн-показы |
| **Объекты** | «Объекты» — таблица с фото, ценой, статусом и эффективностью, редактор с предпросмотром карточки и ссылкой на видео; «Акции»; «Загрузка» — проекты из файла (проекты, только фотографии, только расстояние до пляжа, контакты, тексты, настройки) и выгрузка с сайта |
| **Отчёт** | Итоги недели (открывается на идущей), 30 дней, источники, языки, рассылки, эффективность объектов |
| **Публикации** | «Очередь и история» отложенных постов, «Пост в канал» — оформление, подпись и рубрики, «Каналы и группы» — подключение, права бота, темы |
| **Тексты и контакты** | «Приветствие», «Контакты» (менеджер, каналы связи, «О компании»), «Почему мы», «План покупки», «Автоответы» (и шаблоны), «Подписи бота» — сверху «Если раздел пуст», ниже тексты кнопок и служебных сообщений на всех языках |

Рассылки клиентам отправляются из «Клиенты → База клиентов» и «Публикации»:
точный предпросмотр аудитории по языку, тегу, этапу воронки, источнику и
интересу к конкретному объекту, карточка объекта прямо в рассылке.

Заголовок вкладки показывает, сколько клиентов ждут ответа: «(3) Панель
Telegram-бота». Когда приходит новое сообщение клиента, а вкладка не на виду
(другая вкладка, свёрнутое окно), заголовок мигает «✉ Новое сообщение», пока в
неё не вернутся. Кнопка 🔇/🔊 в шапке включает короткий двойной звуковой сигнал
(по умолчанию выключен; выбор помнится в этом браузере; после перезагрузки страницы браузер
молчит до первого нажатия на ней — это его правило, кнопка 🔊 подскажет). Скрытая вкладка
продолжает спрашивать бота раз в 45 секунд, но экран не перерисовывает — он
обновляется, когда в неё возвращаются.

Кнопка с колокольчиком в верхней панели открывает центр уведомлений. Он
объединяет новые сообщения клиентов, контакты на сегодня и просроченные задачи,
неподтверждённые просмотры, ошибки рассылок и технические проблемы. Уведомление
можно отметить прочитанным или обработанным; эти статусы сохраняются после
перезапуска. Кнопка «Открыть» ведёт прямо к соответствующей переписке, календарю,
рассылке или настройке; уже разобранное можно скрыть кнопкой «Скрыть». Если причина устранена, событие покидает активную очередь,
а обработанная запись остаётся в истории.

В «Диалогах» менеджер может отправить не только текст, но и фотографию JPG/PNG
или документ PDF, TXT, DOC, DOCX, XLS, XLSX. Для ответа на конкретную реплику
клиента нажмите «Ответить» возле неё — выбранная цитата будет видна и в панели,
и в Telegram. Панель показывает состояние доставки. Если сеть оборвалась,
черновик и файл остаются на месте, а «Повторить отправку» использует тот же
идентификатор операции и не создаёт дубль уже доставленного сообщения. Размер
фотографии — до 5 МБ, документа — до 10 МБ; подпись к файлу — до 800 знаков.

Правки в формах не сохраняются сами: внизу появляется полоса «Есть
несохранённые изменения» с кнопками «Сохранить» и «Отменить». Уход со
страницы с несохранёнными правками требует подтверждения.

## Группы и каналы

Новую группу или канал бот замечает сам: как только его добавляют или меняют
права, они появляются в разделе «Рассылки и каналы» → «Группы и каналы».
Ту, где бот уже состоит, подключают вручную: в том же разделе есть поле
«Подключить группу или канал» — введите ID вида -1001234567890 или @имя
канала. Бот должен быть там администратором.

Панель показывает только те действия, на которые у бота есть права в этом
чате. Что доступно:

- отправить сообщение: текст, фотография, кнопка-ссылка, сразу или по
  расписанию; сразу закрепить;
- закрепить и открепить любое сообщение, открепить все;
- удалить сообщение, изменить название и описание группы;
- создать и отозвать ссылку-приглашение;
- принять или отклонить заявки на вступление;
- посмотреть администраторов и забанить участника;
- вывести бота из группы или канала.

В канале бот публикует от имени канала, а в списке видны последние посты.

### Темы группы (подгруппы)

Если в группе включены темы («Управление группой» → «Темы»), в панели у неё
появляется выбор темы: в «Публикации → Пост в канал» — над текстом поста, в
«Публикации → Каналы и группы» — карточка «Темы группы». Пост,
в том числе отложенный, уходит в выбранную тему; «Общая» — основная лента группы.

Чего Telegram не даёт: **списка тем бот получить не может**. Поэтому он
запоминает тему, как только в ней появляется сообщение или служебное событие
(создание, переименование, закрытие, открытие), а недостающую тему можно добавить
по ссылке («Копировать ссылку» в самой теме) или по номеру. Новую тему бот
создаёт сам — для этого ему нужно право «Управление темами». Закрытая или
удалённая тема при публикации даёт понятную ошибку. У сообщений в списке «Что бот
видел в группе» показана тема, из которой они пришли.

### Подпись и рубрики

Вкладка «Оформление постов»:

- **Постоянная подпись** добавляется в конце каждого поста в группу или канал —
  контакты, сайт, ссылки на соцсети. Ссылки Telegram делает кликабельными сам.
  Отдельный пост можно отправить без неё галочкой «этот пост без подписи».
  Переносы строк: «как набрано» оставляет разбивку по строкам, «одной строкой»
  убирает переносы, и Telegram сам переносит подпись по ширине экрана —
  есть и вариант с разделителем «·». Рядом видно, как подпись уйдёт.

  Ссылка надписью пишется как [ТикТок](https://tiktok.com/@аккаунт): в Telegram
  это кликабельное слово «ТикТок». Так же делается ссылкой значок:
  [🎵](https://…). Это работает и в подписи, и в тексте поста; остальной текст
  экранируется, так что символы < > & можно писать как обычно.
- **Кнопки под постом** — до шести кнопок-ссылок, которые добавляются к каждому
  посту (1–3 в ряд). Значок ставится прямо в названии кнопки: «🎵 ТикТок».
  Ряд делится поровну, поэтому длинные подписи обрезаются: при трёх кнопках в
  ряд помещается около 10 знаков, при двух — 16. Панель предупреждает об этом
  в предпросмотре. Стрелку ↗ у кнопок-ссылок рисует сам Telegram, убрать её
  нельзя.
  Логотипы брендов в текст Telegram вставить нельзя — в сообщении доступны
  только обычные символы Unicode, а кастомные эмодзи боту недоступны, поэтому
  кнопки со значком и словом — самый близкий вариант.
- **Рубрики** — картинки-плашки с названием раздела (до 12 штук). При
  публикации вы выбираете рубрику, и плашка уходит вместе с постом. У каждой
  рубрики три варианта размещения:
  - **внизу сообщения** — картинка внутри поста, текст над ней;
  - **отдельным сообщением** — текст уходит обычным сообщением, плашка следом;
  - **над текстом** — плашка становится картинкой поста.

  У сообщения с картинкой ширина равна ширине картинки, поэтому узкая плашка
  сжимает текст: делайте плашки шириной от 1280 точек либо выбирайте
  «отдельным сообщением». Панель показывает размер загруженной плашки и
  предупреждает, если она узкая.

  Telegram вписывает картинку в свой блок: если она вытянута шире 3:1, пустота
  сверху и снизу заполняется размытой копией картинки. Панель это замечает и
  предлагает «Дорисовать фон» — добавляет поля выбранного цвета до 3:1, и
  размытия не будет.

Плашка внизу держится внутри сообщения за счёт подписи над картинкой
(show_caption_above_media). Подпись к фотографии вмещает 1024 знака, поэтому
если текст с постоянной подписью длиннее или у поста своё фото, плашка уходит
отдельным сообщением сразу за постом — панель предупреждает об этом заранее.

Кнопка «Себе для проверки» отправляет тот же пост в админ-чат: видно, как он
встанет, а подписчики ничего не получают.

Чего Telegram не даёт боту: прочитать историю чата и получить список
участников. Панель показывает только те сообщения, которые пришли боту, пока
он в чате (в группе для обычных сообщений в BotFather должен быть выключен
privacy mode; посты канала приходят всегда), и общее число участников или
подписчиков.

## Кнопки для клиента

- Под каждой акцией — «💬 Узнать подробнее»: одно нажатие создаёт обращение по
  этой акции.
- Под карточкой объекта без цены — «💰 Узнать цену»: одно нажатие создаёт
  обращение по объекту.

Тексты этих кнопок редактируются в панели: «Тексты интерфейса» → действия с
объектами.

## Просмотры

- Под уведомлением о записи на просмотр есть «✅ Подтвердить просмотр»:
  клиент получает сообщение с объектом, датой, временем, адресом и кнопкой
  карты — на ту дату и время, что он выбрал. Другую дату и точное время
  задают в панели, в карточке обращения («Подтвердить и сообщить клиенту»;
  повторное подтверждение переносит просмотр).
- Дата из формы сохраняется как настоящая дата для «Сегодня» и «Завтра», а
  для «Другая дата» — если её удалось прочитать из ответа («25.09»,
  «25 сентября», «September 25», «25 de septiembre», «завтра в 16:00»).
  «В выходные» остаётся открытой датой до подтверждения.
- Накануне подтверждённого просмотра в 18:00 клиент получает напоминание с
  кнопкой «Отменить просмотр» (если просмотр подтвердили в тот же вечер —
  не получает).
- На следующий день после просмотра (с 10:00, в течение трёх дней) бот
  спрашивает «Как прошёл просмотр?»: «👍 Понравилось» создаёт обращение для
  менеджера, «🤔 Остались вопросы» ждёт вопрос, «👎 Не подошло» сообщает
  администратору и показывает похожий объект. Ответ виден в карточке
  обращения.
- Утром (в начале рабочего дня, по умолчанию в 8:00) администратор получает
  список просмотров на сегодня и тех, что ждут подтверждения.

### Запись на свободное время

«Настройки» → «Время для просмотров»: дни недели, время начала просмотров
(например, «10:00, 12:00, 16:00»), на сколько дней вперёд можно записаться и
сколько просмотров в одно время (больше одного — если показывают несколько
менеджеров). Когда включено, в форме записи клиент видит только свободные
дни и часы; занятым считается время подтверждённых просмотров, а до начала
должно оставаться не меньше часа. Просмотр сразу подтверждается: клиент
получает подтверждение, администратору приходит уведомление с пометкой
«подтверждён автоматически». Если два клиента выбрали одно время, второй
получает «это время только что заняли» и выбирает снова. «Другая дата» и
«Другое время» остаются — такие просмотры подтверждает менеджер. Пока
настройка выключена, форма работает как раньше.

### Страница «Просмотры»

«Переписка» → «Просмотры» открывает рабочий недельный календарь. В нём видны
загрузка каждого дня, подтверждённые и ожидающие ответа встречи, записи без
точной даты, а также отдельные очереди «Ждут подтверждения» и «История».
Просмотр можно подтвердить или перенести прямо из календаря; перед отправкой
панель показывает дату и время, а после сохранения уведомляет клиента в
Telegram. Из любой карточки открывается связанное обращение.

## Мои заявки

«☰ Ещё» → «📋 Мои заявки» или команда `/requests`: последние пять обращений
клиента со статусом («получена», «в работе», «просмотр подтверждён»,
«завершена», «отменена»). Предстоящий просмотр клиент может отменить здесь
же — после второго подтверждения; администратор получает уведомление, а
обращение закрывается.

## Рабочее время

«Настройки» → «Рабочее время»: дни, начало и конец (по часам этого
компьютера), текст для клиента на трёх языках. Пока настройка выключена,
всё работает как раньше. Когда включена:

- на сообщение или заявку вне рабочего времени бот добавляет «🌙 Сейчас
  нерабочее время — менеджер ответит в понедельник с 9:00…» (`{next}` в тексте
  бот заменяет сам);
- напоминания о заявках и о дате контакта приходят только в рабочие часы;
- утренняя сводка и список просмотров приходят к началу рабочего дня.

## Незаконченные формы

Если клиент начал заявку на звонок, запись на просмотр или подбор и
замолчал, через 2 часа (с 9:00 до 21:00, пока форма не истекла) бот один раз
напоминает: «Вы не закончили… Продолжим с того же места?» с кнопками
«Продолжить» и «Закрыть форму». Тексты — «Тексты интерфейса» → «Состояния и
незавершённые формы».

## Поиск в сообщениях клиента

- Номер объекта («REF-1024», «ref 1024») открывает его карточку. Если номер
  стоит в вопросе («Сколько стоит REF-1024?»), обращение привязывается к
  объекту — менеджер видит, о чём речь.
- Короткое сообщение с названием города из каталога («Бенидорм», «malaga»)
  показывает объекты в этом городе (фильтр можно сбросить кнопкой). Название
  района также распознаётся: бот определяет его город по каталогу, если это
  однозначно.
- Понятный запрос обычной фразой — например, «ищу купить квартиру в Марбелье
  от 300 до 500 тыс. €, 2 спальни», `from 300k to 500k` или
  `entre 300 y 500 mil euros` — сразу применяет тип сделки, тип объекта,
  город, район, обе границы бюджета и число спален. Поддерживаются также
  короткие записи вроде `300–500 тыс.` и `€300k–€500k`; сокращение у одной
  границы применяется к обеим. Бот не принимает диапазон лет или «от 3
  спален» за цену. Подходящие карточки можно листать как обычный каталог.
- Под отфильтрованным каталогом есть «Передать параметры менеджеру»: заявка с
  теми же критериями и найденными объектами создаётся одним нажатием.
- Неизвестный город или район, несколько мест через «или» и неоднозначная фраза не
  угадываются — такое сообщение, как раньше, получает менеджер. Автоответы
  срабатывают раньше поиска.

## Калькулятор покупки

«Настройки» → «Калькулятор покупки». У объектов на продажу с ценой в
«Подробнее» появляется «🧮 Расчёт покупки и ипотеки»: налоги и расходы сверх
цены (для новостроек — НДС и гербовый сбор, для вторичного жилья — налог на
передачу), итог, платёж по ипотеке и сумма на старте, с пометкой, что расчёт
примерный. Ставки задаются в панели; по умолчанию калькулятор выключен —
проверьте ставки у гестора или нотариуса, прежде чем включать.

## Уведомления и отписка

«☰ Ещё» → «🔔 Уведомления»: клиент сам включает и выключает «Новости и
акции» (рассылки) и «Объекты» (снижение цены и новые объекты по его
запросу). Под каждой рассылкой бот добавляет кнопку «🔕 Отписаться от
рассылок»; после неё клиент получает подтверждение с кнопкой «Вернуть
рассылки». Отписавшиеся не попадают в рассылки и в оценку числа получателей;
в карточке пользователя это видно. Ответы менеджера и сообщения по заявкам
приходят всегда.

## Статистика рассылок

Telegram не сообщает боту о нажатии кнопки-ссылки, поэтому рассылка
оценивается по тому, что получатели сделали в боте в течение трёх дней
после неё: «откликнулись» (написали или нажали кнопку), «заявок» (оставили
обращение), «отписались». Каждый человек считается один раз. Цифры видны в
истории рассылок; у рассылок, отправленных до этой версии, их нет.

## Доступ к панели из интернета

«Настройки» → «Доступ к панели из интернета» → «Включить». Бот запускает
`cloudflared.exe` (должен лежать в папке бота; скачивается с
https://github.com/cloudflare/cloudflared/releases, файл
`cloudflared-windows-amd64.exe`, переименовать в `cloudflared.exe`) и
открывает временный туннель Cloudflare без учётной записи. Адрес вида
`https://<слова>.trycloudflare.com` бот присылает в админ-чат Telegram и
показывает в настройках; при каждом перезапуске бота адрес новый.

Безопасность:

- Включить доступ можно только при подтверждённом админ-чате в Telegram.
- Вход из интернета — пароль и одноразовый шестизначный код, который бот
  присылает в админ-чат (действует 5 минут, не больше 5 попыток). На этом
  компьютере вход по-прежнему только по паролю.
- Запрос считается удалённым, если пришёл через прокси (заголовки
  Cloudflare, `X-Forwarded-*`), с другого компьютера или на не-локальное
  имя. Первичная настройка бота через туннель недоступна.
- Лимит попыток входа считается по реальному адресу посетителя, cookie
  сессии по https получает флаг `Secure`.
- Панель отвечает только на адрес текущего туннеля; после выключения старый
  адрес перестаёт работать.

Временный туннель Cloudflare предназначен для личного пользования и не
гарантирует постоянную работу.

**Постоянный адрес.** В сети, где сейчас работает бот, сервис временных
туннелей (`api.trycloudflare.com`) недоступен: соединение с ним не
устанавливается, тогда как остальные адреса Cloudflare и серверы постоянных
туннелей (`region1/2.v2.argotunnel.com:7844`) доступны. Бот в этом случае
пишет в настройках, что временный туннель заблокирован. Рабочий вариант —
постоянный туннель через учётную запись Cloudflare:

1. В панели Cloudflare: Zero Trust → Networks → Tunnels → Create a tunnel
   (Cloudflared).
2. В Public Hostname указать адрес, например `panel.<ваш домен>`, и сервис
   `http://127.0.0.1:3000`. Домен должен обслуживаться Cloudflare.
3. Скопировать токен туннеля (длинная строка из команды установки).
4. В панели бота: «Настройки» → «Доступ к панели из интернета» → «Постоянный
   адрес через учётную запись Cloudflare» → адрес и токен → «Сохранить».

Токен хранится в `bot-data.json`, в браузер не передаётся, а в `cloudflared`
попадает через переменную окружения `TUNNEL_TOKEN`, не через командную
строку. Если туннель падает, бот перезапускает его через 30 секунд, затем всё
реже — до раза в 10 минут; причина видна в настройках и в журнале ошибок.

## Что видит клиент

Главное меню — короткие кнопки в несколько рядов:

| | |
|---|---|
| 🏘 Объекты | ✨ Подбор |
| 💬 Связаться | 🔥 Акции · N |
| 🇪🇸 Как купить | 👤 Моё |

«💬 Связаться» открывает способы связи с менеджером. Если в «Тексты и контакты → Контакты» загружено фото менеджера, оно стоит над экраном с именем; там же видно, задан ли срок ответа («Обычно отвечаем за …», его выбирают в «Настройки → Компания»). Число у «🔥 Акции» — сколько
акций действует сейчас. «🇪🇸 Как купить» — гид по покупке в Испании с кнопкой
бесплатной консультации. В «👤 Моё» — избранное, сравнение, сохранённый поиск,
недавно просмотренные, мои заявки, уведомления, мои данные, о компании, помощь и
смена языка. Кнопка WhatsApp открывает чат с готовым текстом в поле ввода: с экрана связи — приветствие, с карточки объекта — «Интересует объект: название (номер)» на языке клиента (тексты `whatsappHello` и `whatsappHelloProperty` правятся в «Все подписи бота»). Если владелец вписал в свою ссылку `?text=`, его текст остаётся. Кнопки прежних меню, которые остались у клиентов в чате,
продолжают работать. Подписи меняются в «Тексты бота → Приветствие и меню»; при
обновлении данных подписи и тексты, которых администратор не менял, заменены
новыми, а изменённые им сохранены.

Карточка объекта в каталоге собрана по единому шаблону: выделенное название,
статус, тип и сделка, цена (с символом валюты: €, $, £), город и район,
характеристики с локализованными подписями и первый абзац описания без списков.
Смысловые блоки разделены воздухом, а характеристики стоят не более чем по две
в строке. Полный адрес, состояние, номер объекта и описание целиком открываются
по кнопке «📋 Подробнее» и там также разбиты на озаглавленные блоки.
Предпросмотр в редакторе объекта повторяет карточку Telegram; подписи полей для
русского, английского и испанского меняются в «Тексты интерфейса». На телефоне
основные действия получают всю ширину:
«💰 Узнать цену» (если цена не указана), «📅 Записаться на просмотр»,
«📋 Подробнее» и «💬 Связаться с менеджером». Только две короткие вторичные
кнопки стоят рядом: «❤️ В избранное» и «⚖️ Сравнить». После нажатия их подписи
остаются короткими на русском, английском и испанском; слишком длинная подпись,
заданная администратором, аккуратно сокращается. Активный фильтр показывается
компактно как «Фильтр ✓», а не длинной строкой поверх кнопки. Для
забронированного объекта кнопки просмотра нет — в «Подробнее» есть «Уточнить
доступность». В «Подробнее» и в меню менеджера доступна кнопка «🏘 Похожие
объекты». Она открывает отдельный мини-каталог с навигацией и поясняет, что
именно совпало: тип, город, район, цена, число спален или площадь. Объекты с
другой целью сделки в этот список не попадают. Если у объекта указана ссылка на
видео, в карточке есть кнопка «🎥»; каталог можно листать «Списком» — компактно,
по восемь объектов на странице.

В анкетах короткие варианты ответа стоят по два в ряд (время вида «10:00» — по
три), «✅ Отправить» — отдельной строкой сверху.

## Язык клиента

Если язык Telegram клиента — русский, английский или испанский (`en-US` тоже
считается английским), бот при первом обращении сразу здоровается на нём, без
выбора языка. Остальным (например, с украинским Telegram) показывается выбор из
трёх языков. Сменить язык можно в любой момент: «👤 Моё» → «🌐 Сменить язык»
или команда /language.

Панель подсвечивает оранжевым английские и испанские поля объекта и акции, в
которых есть кириллица («Похоже, текст на русском»), а в сводке готовности
пишет «перевод: город» и т. п.

## Уведомления клиентам об объектах

- **Избранное:** если у объекта из избранного снизилась цена или он снова
  стал доступен (был в резерве, продан или скрыт), клиент получает карточку с
  пометкой «📉 Цена снизилась» или «✅ Снова доступен».
- **Подбор:** когда публикуется новый объект, он приходит клиентам, которые за
  последние 90 дней заполнили «✨ Подбор», если подходит под их
  пожелания: тип сделки, тип недвижимости, спальни (не меньше), бюджет (с
  запасом 10%), район.
  Если у объекта не указаны цена или спальни, это его не исключает. Район
  сравнивается по словам из запроса с городом, районом, адресом и названием
  объекта на любом языке.

Уведомления уходят после сохранения объекта в панели — панель пишет,
скольким клиентам. О каждом изменении клиент узнаёт один раз. Под каждым
уведомлением есть кнопка «🔕 Не присылать такие уведомления». Пока бот
выключен в настройках, уведомления не отправляются. Тексты — в «Тексты
интерфейса» → «Уведомления об объектах».

## Источник клиента

Ссылка `https://t.me/<бот>?start=src_<метка>` (метка — латиница, цифры, `-`,
`_`) запоминает, откуда пришёл клиент: по первой ссылке, повторно не
перезаписывается. Метка видна в карточке пользователя, в уведомлениях об
обращениях («📣 instagram»), в колонке «Источник» выгрузки и в ежедневной
сводке («Новых клиентов: 3 (instagram — 2, без метки — 1)»). Ссылку
удобно собрать в панели: «Настройки» → «Ссылки с меткой источника».

На главной панели карточка «Откуда приходят клиенты»: по каждой метке —
сколько клиентов пришло всего и за 30 дней и сколько из них оставили заявку
или задали вопрос (с процентом).

## Подбор объекта

«✨ Подбор» — мастер из пяти вопросов, который живёт в одном сообщении и
переписывает его на каждом шаге: сделка (покупка или аренда), тип (квартира, дом
или вилла, участок, коммерческая, не важно), город, бюджет, спальни. Для участка
и коммерческой недвижимости вопрос о спальнях пропускается. Кнопки «Начать
заново» и «Передать менеджеру» есть на каждом шаге. Если по условиям ничего нет,
бот не оставляет клиента в тупике: предлагает ослабить условия или передать
запрос менеджеру. Найденные объекты листаются как каталог («✨ По вашему
запросу»); менеджер получает заявку с условиями подбора.

## Загрузка объектов с сайта

«Объекты» → «⇩ Загрузить с сайта»: ссылка на XML-выгрузку для порталов в
формате Kyero (её обычно отдаёт сайт агентства или CRM) или файл выгрузки.
«Проверить» показывает, сколько объектов добавится и обновится, ничего не
меняя; «Загрузить» применяет. Объекты сопоставляются по номеру (`<ref>`):

- новые добавляются скрытыми (или сразу видимыми, если отмечено и есть фото);
  название, если его нет в выгрузке, собирается из типа и города;
  фотографии скачиваются по ссылкам (до 10, JPG/PNG до 5 МБ);
- у существующих обновляются цена, сделка, тип и характеристики; названия,
  описания и фото, заполненные в панели, не меняются (пустые заполняются);
- объекты, которых больше нет в выгрузке, не удаляются — их список виден
  после загрузки.

Номера сравниваются как написаны (без учёта регистра и пробелов по краям):
«A-1» и «A1» — разные объекты. Поля, которых нет в выгрузке, не меняются.
HTML в описаниях превращается в обычный текст. За одну загрузку скачивается
не больше 300 фото и не дольше 10 минут (каждое — до 5 МБ, 15 секунд);
остальные фото докачает следующая загрузка. Фото по адресам внутри локальной
сети не скачиваются. Две загрузки одновременно не идут. Уведомления клиентам
о новых объектах после загрузки — не больше одного на человека.

С отметкой «Обновлять каждый день» бот сам загружает выгрузку по ссылке раз
в сутки, с 9:00 до 20:00; ошибки видны в окне загрузки и в журнале ошибок.

## Объекты в панели

- На карточке объекта — статистика: 👁 показы, 📋 «Подробнее», ❤️ избранное,
  📩 заявки и вопросы по объекту.
- «⧉ Копия» создаёт копию объекта со всеми полями и фотографиями (фото не
  дублируются на диске), без номера, со статусом «Скрыт» — чтобы быстро
  добавить похожий объект.
- Стрелки ↑ ↓ меняют порядок: в каталоге бота объекты идут так же, как в
  панели. При поиске или фильтре в панели стрелки неактивны.

## Фильтр каталога

Под карточкой каталога доступен «🔎 Фильтр»: сделка (продажа/аренда), тип
(только те, что есть в каталоге), спальни (1+…4+), город, район, цена «до …»
и сортировка. Районы появляются после выбора города, поэтому варианты не
смешиваются между разными городами. У каждого варианта показано число
результатов; заведомо несовместимые варианты скрываются, а выбранный вариант
остаётся видимым, даже если временно даёт ноль объектов. Длинные варианты
города и района стоят по одному в строке. Если городов или районов больше
четырёх, основной фильтр остаётся коротким: выбор открывается отдельно,
по шесть вариантов на страницу, с понятным возвратом к фильтру. Остальные
кнопки стоят не более чем по две в ряд, чтобы подписи не обрезались на
телефоне. Цена и сортировка показываются как
«сначала дешевле / дороже». Шкала цен своя для продажи (до 150 000 € … до
1 000 000 €) и для аренды (до 800 € … до 3 000 € в месяц); она появляется,
когда выбрана сделка или в каталоге только один тип сделки. Кнопка «Показать»
сразу пишет, сколько объектов подходит. Кнопки «Цена от» и «Своя цена»
принимают нижнюю и верхнюю границы бюджета в привычной записи (`525 000 €`,
`525 тыс.`, `1,2 млн`) и возвращают клиента в тот же фильтр. Бот не принимает
нижнюю границу выше верхней, а ошибочная сумма не превращается в обращение к
менеджеру. Диапазон сохраняется вместе с поиском и используется в уведомлениях
о новых подходящих объектах. Фильтр запоминается у клиента,
выбранные условия видны на кнопке. Если ничего не найдено, бот предлагает
сбросить фильтр или оставить пожелания через подбор. При фильтре по спальням
или цене объекты без этих данных не показываются; при сортировке объекты с
ценой по запросу идут последними. На избранное фильтр не действует.

## Шаблоны ответов

Кнопка «✎ Шаблоны ответов» в разделе «Обращения» открывает список готовых
ответов на частые вопросы (до 50). У шаблона есть название и текст на русском,
английском и испанском; достаточно заполнить один язык.

В форме ответа на обращение над полем текста шаблоны стоят кнопками в ряд —
на телефоне ряд листается вбок, кнопки высокие, под палец. Одно нажатие
вставляет шаблон на языке клиента (если перевода нет — на русском),
`{first_name}` заменяется на имя клиента при отправке. Набранное не стирается:
если в поле уже что-то написано, шаблон добавляется ниже через пустую строку,
курсор встаёт в конец. Текст можно поправить перед отправкой.

## Выгрузка в Excel

Кнопка «⬇ Выгрузить в Excel» в разделе «Обращения» скачивает файл `.xlsx`
ровно с теми обращениями, которые сейчас видны в списке, то есть с учётом
поиска и фильтров по статусу и типу. Колонки: даты создания и обновления
(настоящие даты Excel), статус, тип, клиент, username, телефон, имя и удобное
время из заявки, язык, объект, текст обращения, заметка администратора, число
ответов, последний ответ и ID обращения. Первая строка закреплена, на ней
включён фильтр.

**Клиенты.** Кнопка «⬇ В Excel» в «Клиенты → База клиентов» выгружает таблицу с
теми, кого показывает список (учтены этап и поиск): одна строка — один человек.
Колонки: клиент, username, телефон, имя и удобное время для связи, язык,
источник, этап работы, следующий шаг, число обращений и последнее из них,
избранное, согласие на рассылки, доступность бота (не заблокировал ли он его),
теги, заметка, даты первого визита и последней активности, ID. Файл содержит
персональные данные клиентов — храните его так же бережно, как саму базу.

Файл собирается без сторонних библиотек (`xlsxWorkbook` в `src\excel.mjs`). Текст
пишется в строковые ячейки, поэтому сообщение клиента вида `=…` в Excel
остаётся текстом и не выполняется как формула.

## Безопасность

- Панель слушает только 127.0.0.1, запросы с чужим заголовком `Host`
  отклоняются.
- Скрипт панели запускается только с одноразовым nonce из заголовка CSP;
  внедрённые `<script>` и обработчики событий браузер блокирует.
- Смена пароля и токена требует текущий пароль; вход ограничен 10 попытками
  за 15 минут; тело запросов без авторизации — не больше 16 КБ.
- `tests\security.test.js` проверяет эти сценарии.

## Сборка exe

`build.ps1` (`npm run build`) по шагам:

1. Если esbuild ещё не установлен — `npm ci` (версия закреплена в
   `package-lock.json`).
2. Проверяет синтаксис каждого `src\*.mjs` и запускает тесты.
3. `npm run bundle` — esbuild собирает `src\entry.mjs` со всеми модулями в один
   файл `dist\bot.bundle.cjs`. Это нужно, потому что в собранном exe
   `require()` умеет загружать только встроенные модули Node.
4. Собирает SEA-блоб по `sea-config.json` (там же перечислены картинки, которые
   встраиваются в exe) и встраивает его в копию `node.exe` через `postject`
   (скачивается через `npx` при первой сборке).

Результат — `dist\bot.exe`. Рабочий `bot.exe` скрипт не трогает: чтобы
обновить бота, остановите его, сохраните прежний файл в `backups\` и замените
(подробнее — в [docs/runbook.md](docs/runbook.md)).

`src\entry.mjs` — точка входа exe: с ключом `--reset-password` запускает смену
пароля (без чтения данных бота и без открытия порта), иначе — обычный запуск
`src\main.mjs`.

## Устройство кода

`bot.js` — только точка входа для запуска из исходников: указывает папку
данных и загружает `src\main.mjs`. В собранном exe точка входа — `src\entry.mjs`:
она выбирает между обычным запуском и `--reset-password`. `main.mjs` загружает модули в определённом
порядке и запускает бота (кроме случая `BOT_NO_START=1`).

Порядок важен: `config`, `util`, `data-format`, `media` и `texts` не
зависят от данных и не должны импортировать `store`. `store` читает
`bot-data.json` прямо при загрузке, остальные модули пользуются данными
только во время работы. Весь объект данных заменяется только через
`replaceData()` из `store.mjs` (восстановление из резервной копии, тесты);
остальные модули видят новое значение автоматически.
