### 6.1. Ошибки, которые проявятся в работе

- [x] Сообщение участника группы идёт по сценарию клиента — исправлено:
      в группе и канале бот молчит (кроме группы, назначенной чатом
      администратора), реакции и нажатия кнопок в группе не заводят клиента с
      номером группы. 5 тестов в groups.test.js, проверено падением без
      исправления
- [x] Флаг `blocked` не снимается сам — исправлено: технический запрет от
      Telegram снимается любым входящим сообщением клиента и сигналом
      `my_chat_member` → `member`, а галочка панели «не писать этому клиенту»
      теперь отдельная (`blockedBy: admin`) и сама не снимается. 4 теста,
      проверено падением без исправления
- [x] Рассылка при сбое связи засчитывала оставшихся как неудачу — исправлено:
      сетевая ошибка, 5xx и 429 переводят рассылку в `queued` с пометкой
      «пауза, продолжится сама», получатель не помечается обработанным и
      получит сообщение при следующем проходе (каждые 30 с, когда связь есть).
      Отказ конкретного клиента (403) по-прежнему просто неудача
- [x] Поиск фразой — исправлено: слова-указатели («до», «от», «до»…) ищутся
      целиком, между словом и суммой допускаются только пробелы, знаки и
      короткие связки («чем», «около», `than`), сумма без валюты ниже 100 не
      считается ценой. «300к» понимается как 300 000. Бюджет подбора сведён к
      общему разборщику `largestMoneyAmount` в `util.mjs`: «€350,000», «300к»,
      аренда «до 800» читаются верно. 8 тестов в `search-phrases.test.js`,
      проверено падением без исправления
- [x] Панель: поле «Новый токен» не отправлялось — исправлено. Смена токена
      стала отдельным действием: поле «Текущий пароль панели», кнопка «Сменить
      токен» с подтверждением; автосохранение настроек токен не отправляет.
      Проверено вживую: неверный пароль → отказ с текстом, верный → сервер
      проверяет токен в Telegram. Заглушка браузера в тестах теперь помнит
      найденные элементы и записывает запросы, поэтому «кнопка ничего не
      отправляет» ловится тестом
- [x] Панель: восстановление копии не работало — исправлено. Файл уходит на
      сервер байтами (чтение текстом раздувало копию с 16 до 29 МБ и ломало
      её), в выборе файла теперь видны `.json`, `.gz` и `.kbk`, пароль
      спрашивается только для `.kbk`, после восстановления показывается число
      ненайденных фотографий. Проверено на настоящем сервере: копия 15,4 МБ
      восстановилась, та же копия «текстом» → отказ, `.kbk` без пароля →
      отказ, с паролем → успех. 4 теста в `panel-render.test.js`
- [x] Панель: автообновление стирало введённое — исправлено. Обновление
      спрашивает сервер с `?since=`: если ничего не изменилось, экран не
      трогается вовсе. Если изменилось, но на экране что-то набрано (или курсор
      в поле) — данные обновляются в фоне, а внизу появляется полоска
      «Появились новые данные · Обновить экран». Прокрутка наверх — только при
      переходе между разделами. 4 теста через сам таймер панели, проверено
      падением без исправления; вживую черновик поста в канал уцелел
- [x] Сбой записи данных — исправлено: запись повторяется до четырёх раз с
      растущей паузой при временной блокировке (EPERM/EBUSY/EACCES), при
      нехватке места повтора нет; сбой попадает в журнал ошибок и уходит
      администратору (не чаще раза в час), отложенное сохранение повторяется
      с растущей паузой до минуты; недописанный `.tmp` убирается. Неудачная
      копия `.bak` больше не мешает записи. 5 тестов в `saving.test.js`,
      проверено падением без исправления
- [x] Рассылка перезаписывала файл каждые ~150 мс — исправлено. Причина была
      глубже ветки `else`: сохранение планировали и другие места внутри
      доставки, поэтому на время рассылки частые записи отключены целиком
      (`store.mjs scheduleSave`), файл пишется раз в 5 с и в конце.
      Измерено: было 6 записей на 12 получателей, стало 2
